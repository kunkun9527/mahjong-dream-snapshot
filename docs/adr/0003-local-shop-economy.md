# ADR 0003：离线商店与一次性初始补给

## 决策

按用户确认的方案，现有档案与新档案都进行一次初始升级：三麻、四麻均为原客户端的“御龙七段”；商店货币初始化为 999999，雀币按该档案初始化前的余额乘以 100。本地结算金币字段也初始化为 999999。

使用独立的 `offlineEconomyVersion` 标记补给版本，保留现有 `profile.version`、昵称、装备、设置和累计战绩。之后段位按比赛结果正常升降，商店消费正常扣除；登录、查询、重连及重启均不得再次补满。

四类商店沿用原客户端界面和本构建的商品配置、消息协议，不套用其他麻将游戏的协议。服务端决定商品、价格、库存与购买限制；客户端提交的价格不能作为扣费依据。

扣费和发货必须先整体校验再提交，失败不得留下部分库存变更。成功通过原有 `DataChangeNotify` 更新界面，大厅库存与补给标记仍由 Node 服务保存到同一份原子替换的本地档案。不得直接编辑运行时 `userdata/profile.json`。

## 边界

- 不接入支付、充值或其他远端服务；招募商店兑换不等于实现招募抽卡。
- 保留既有角色、外观与最高好感度的离线解锁，不通过本轮修改重新锁定它们。
- 不改变已完成比赛的累计统计规则，也不新增比赛历史或牌谱存储。
- “御龙七段”是初始段位而非永久锁定段位；后续降段可重新影响房间门槛。
- 原表七段为17级、2300 PT，满足乘风/御龙；用户已确认不移除启航/逐梦的段位上限，因而不承诺所有房间同时可进入。
- 原有普通请求50ms合并保存策略不等于购买响应前已写盘；仍应正常关闭服务，不能承诺强制杀进程/断电不丢最后一笔操作。
